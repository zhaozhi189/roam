# ADR-013 · 步行碰撞:splat 体素占据网格(F-12,关闭 Q8)

- 状态:✅ 已采纳并实现(2026-06-12)
- 关联:doc/01 Q8(MVP 砍掉物理碰撞 → Phase 2 重启)、F-12、ADR-009(indoor 步行模式)

## 背景

MVP 阶段 Q8 决定砍掉物理碰撞(主理人自己控走位、接收方只看视频)。Phase 2 的 F-12
要求重新启用:indoor 步行模式(M5-1 🚶)目前可以穿墙,自己漫游时出戏。

约束:3DGS 场景没有 mesh,传统 raycast / 物理引擎(ammo/cannon)无从挂起;
项目原则是零新依赖、KISS。

## 决定

**用 splat centers 构建体素占据网格,步行每帧查表拦截**:

- splat centers 已有现成通道(F-10 标注的 `splatCenters()`,从 resource 直读 Float32Array)
- 0.25m 体素,**体素内 ≥4 个 splat 才算实体**(滤孤立 floater),packed int 入 `Set`
- 1024³ 网格覆盖 ±128m,场外 floater 直接丢弃
- 步行时对「下一步位置」查 3x3x3 邻域(≈0.25~0.37m 碰撞半径),撞实体则该帧不前进,
  **不打断 walking 状态**(用户转向即可继续走)
- 网格按 resource 缓存、首次按需构建,切场景自动失效
- ⑨ 设置面板「步行碰撞」开关(默认开),localStorage 持久化

## 实测(2026-06-12,桌面 Chrome + 公寓 SOG)

- 66 万 splat → 11649 实体体素,构建 **20ms**(一次性)
- 定向撞墙对照:**开碰撞 1.46m 停在墙前(墙距 1.5m),关碰撞 2.97m 直接穿墙**
- 每帧开销 ≤27 次 Set 查找,可忽略

## 备选方案

| 方案 | 不取理由 |
|---|---|
| 物理引擎(ammo.js/cannon-es) | 新 vendor 依赖;3DGS 仍要先生成碰撞体,没解决根本问题 |
| 从 splat 重建 mesh(Poisson 等) | 离线工具链复杂度暴涨,室内扫描质量不稳 |
| raycaster 软碰撞(Q8 原案 c) | PlayCanvas raycast 不支持 gsplat;自实现射线-点云逐帧查询比体素查表贵 |
| 距离场(SDF)烘焙 | 精度更好但构建成本高,0.25m 体素对步行(0.6m/s)足够 |

## 后果

- ✅ 零依赖、零离线步骤,任何场景(内置/自扫/SAF 导入)加载即有碰撞
- ✅ 开关可关,旧行为可回退
- ⚠️ **扫描缺失区拦不住**:室内扫描墙体常不完整(公寓实测 8 个方向只有 3 个有墙数据),
  数据里没有的墙不可能挡 —— 这是数据问题不是算法问题,自扫时多绕几圈墙体可改善
- ⚠️ 体素 0.25m 粒度下,薄物体(玻璃/栏杆)若 splat 稀疏会漏判

## 何时回头看

- 自扫场景普遍反馈「该挡没挡」→ 降 COLL_MIN 或体素加密到 0.15m(内存×4.6)
- 如果未来做 F-14 多场景拼接,网格要支持多 resource 合并
