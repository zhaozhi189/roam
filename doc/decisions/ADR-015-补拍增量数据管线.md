# ADR-015 · 补拍/增量数据管线 — 不清晰处补拍,把重复工作降到「只重训」

## 背景

自扫场景训完后,某些区域不清晰(视角不足 / 覆盖不够 / 帧太少 / 运动模糊)。诉求:**对着不清楚的那块补拍照片/视频,增量补进去,尽量不从头重训**(zhi 原话「像修 bug 一样补充,减少重复工作」)。

问题是 3DGS 的产物(`.ply`)是**一整团高斯**,没有「局部图层」可单独编辑;某块要变清晰,本质是**那块需要更多视角的图像参与训练**。于是核心问题变成:**能不能把已训练的模型当起点,只加新图增量续训,而不是全量重训?**

## 调研结论(2026-06-13,advisor 查证,证据见末尾)

**Brush 不支持真正的增量续训,连「取巧」路径都已被实测证伪:**

| 设想的增量路径 | 实际行为 | 证据 |
|---|---|---|
| 已训练 `.ply` 喂回去当 warm-start | Brush 只当它是**初始点云**,走 KNN 重新初始化,**训好的 scale/rotation/opacity/SH 全被丢弃重算** = 等于用更密的点云从头训 | DeepWiki 数据格式;`train_stream.rs` `to_init_splats`(行 ~107-139) |
| `--start-iter` 从中途恢复 | **只影响学习率调度计数器**,不加载任何训练状态 | PR #138;DeepWiki 4.1/4.5 训练循环无 checkpoint 加载路径 |
| 有 checkpoint 存档 | 导出只有 `.ply`,**不含优化器动量 / 致密化 / refinement 状态** | `--export-*` 只出 ply;Issue #176 |
| 社区做出来了 | Issue #29/#176/#215 三个 resume 请求,**无 PR、无 fork、无路线图**,#176 至今 Open 作者未回 | GitHub issues |

**实测证伪**:#176 用户拿 85% 的导出重启续训,**质量明显下降**——优化器动量清零导致高斯塌缩。

**唯一真正省时的抓手在 COLMAP 不在训练**:补拍的新帧可用 `image_registrator` **增量注册**进已有 `sparse/`(老帧 SfM 不重算)。但 Brush 训练那 30-60 分钟**省不掉,必须全局重训**。

## 决策

**补拍 = 「素材累积 + COLMAP 增量注册 + 降步数全局重训」,不追求训练增量。**

明确管理预期:**没有「几秒补一块」**。补拍能省的是「不用重拍老素材、COLMAP 不全量重算」;不能省的是「每次补完要等一次(更短的)重训」。

### 边界(明确不做)

- ❌ 改 Brush 源码做 warm-start(优化器状态全在内存、不可序列化,比换工具还贵)
- ❌ 换训练器(GSTK 支持「编辑-续训」但要 **CUDA**,跟 Mac Metal 流程不兼容,违 ADR-010)
- ❌ 在 `.ply` 上做局部 PS 式贴图(3DGS 无此语义)

## 设计

### 1. `scan-train.sh` 增强:支持增量补拍

新增第 5 参或一个 `--append` 路径,语义:**复用已有工作目录,只把新视频/图像的帧加进去增量重建 + 降步数重训**。

```
# 首次(现状不变)
./scripts/scan-train.sh room.mp4 ~/roam-room-test 30000 scene

# 补拍(新):把 patch.mp4 的帧增量并入 ~/roam-room-test 重训
./scripts/scan-train.sh patch.mp4 ~/roam-room-test 15000 scene --append
```

`--append` 分支:
1. **抽帧**:新视频抽帧追加到 `images/`(文件名续号,不覆盖老帧)
2. **COLMAP 增量**:对新帧 `feature_extractor`(复用已有 `colmap.db`)+ 跟全库 exhaustive 匹配 + `image_registrator` 把新帧注册进已有 `sparse/0`(老帧位姿不动)
3. **重训**:Brush 用合并后的全图重训,步数可降(已有好的 SfM 点云打底,默认 `--append` 给 15000)
4. 后处理 / 压缩同现状

### 2. ADR-014 引导录制联动:补拍模式

ADR-014 的引导录制加一个**「补拍」preset**:引导用户「凑近不清楚那块、多角度慢慢拍,**务必带到旁边认得出的参照物**」(重叠是 COLMAP 把新帧拼进老坐标系的前提)。补拍视频走 `scan-train.sh ... --append`。

> 顺序:先做 ADR-014 基础引导录制 + 本 ADR 的 `--append` 管线;补拍引导 preset 待基础闭环跑通、真见到「哪块糊」后再设计。

## 备选方案

| 选项 | 评价 | 没选的原因 |
|---|---|---|
| A · 每次全量重训(含重拍老素材) | 0 改动 | 老素材重拍 + COLMAP 全量重算,纯浪费 |
| B · 改 Brush 源码加真 warm-start | 理论最优 | 优化器 lazy-init + 状态全在内存,序列化改造极贵,还要解决动量缺失塌缩 |
| C · 换支持 checkpoint 的训练器(GSTK/nerfstudio) | 真增量 | 要 CUDA,Mac Metal 流程不兼容,违 ADR-010 锁定 |
| **D · 素材累积 + COLMAP image_registrator 增量 + 降步数全局重训** ✅ | 不换工具、不违 ADR-010、把可省的(老素材/SfM)都省了 | (本项) |

## 后果

### 好的影响

- **老素材不重拍、COLMAP 不全量重算**——把「重复工作」压到只剩训练一步
- 不引入新工具链,不违 ADR-010 / CLAUDE.md 的 Brush 锁定
- 与 ADR-014 引导录制天然配套(补拍引导 → `--append` 管线)
- advisor 调研结论沉淀在案,**以后不用再为「Brush 能不能增量」重复踩坑**

### 不好的影响 / 取舍

- 训练仍要全局重跑(虽降步数),不是「秒级补丁」,**预期要讲清楚**
- `image_registrator` 增量注册若新帧与老场景重叠不足会注册失败 → 退化为全量重建
- `scan-train.sh` 增加 `--append` 分支,脚本复杂度上升(可控)

## 何时回头看

- Brush 出真 checkpoint / warm-start(关注 issue #176)→ 升级为训练增量,省掉重训
- 换到 CUDA 机器 → 可评估 nerfstudio splatfacto / GSTK 的真增量续训
- WebGPU/Metal 训练器生态成熟出可 resume 的方案 → 重新评估
